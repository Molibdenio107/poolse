# Poolse — 29 Aug

Round 4. Five commits, 43 files, ~3k lines. All green: both typechecks, 51 web tests,
59 API tests, 26 SQL suites, i18n, layout, contrast, the Portuguese checker.

## What went in

**The app looks like one app now.** Pages were full-bleed, which is fine on a laptop and
silly on a 27-inch monitor — a table row putting the name and its action a forearm apart.
Content caps at 80rem, controls are all 36px, and the sixteen forms that predated
`field.tsx` and kept their own copy of the old class string now import the shared one. That
last part is the bit that matters: without it half the app would have been 36px and half
40px, which is worse than either. Number spinners gone. Menu reordered — Instalações first.

**Dashboard and My profile swapped what they were carrying.** The dashboard had become a
worse version of Instalações: the org's name, its licence, a count of facilities and pools
that Instalações lists properly one click away. It's now about *you* — who you're signed in
as, your roles, your devices. Licence, organizations and transfer of ownership moved to the
profile, where anyone would actually go looking for them.

**A site can say when it's open.** This is the one I'd keep if I could only keep one.
`facility_hours` — seven rows per site, ISO weekday, matching `class_schedule`. Closing a
day blocks the *next* class and leaves the ones already there alone, enforced by a trigger
on `class_schedule` rather than by hiding a control. Refusing the edit would have deadlocked
the operator: can't close the day until the classes move, and the reason the classes are
moving is that the day is closing. The grid shows how many turmas already use a day
*before* you switch it off.

Default is open-all-day rather than an invented 08:00–22:00 — which would have silently
invalidated the 23:30 Azores lane-hire class sitting in our own test suite. Small thing,
but that's exactly the class of bug that ships.

**Pool detail got two blocks.** Water quality is a placeholder, deliberately shaped like the
real thing (pH/temperature/analysis tiles, and the disabled import-a-report control). Kit
inventory is real: free-text name and a count. Not a dropdown of approved equipment types —
that fails on the first club that keeps arcos, and then those arcos live in a notes field
forever. Not a stock ledger either; a ledger nobody posts to drifts from the shelf in a
month and is then wrong with more precision than a count was.

**Back navigation was actually broken.** Click "6 Instrutores" on a site, then Voltar, and
you landed on the dashboard. Fixed with `?from=` rather than `history.back()`, and the value
is validated as an internal path — a back button is a redirect wearing a coat.

## Friction worth noting

Most of the evening went to tooling, not code. The remote workspace on the PC wouldn't
start, which meant no direct shell into the repo, which meant a one-file-at-a-time bridge
that refuses anything deeper than seven folders — i.e. most of `dashboard/facilities/`.
Ended up pushing to GitHub and working from a clone, delivering a patch back. Worked, but
it's an hour that bought nothing.

Silver lining: the cloud box ran Postgres 16 natively, so every migration and all 26 SQL
suites actually executed rather than being reasoned about.

## Is this going the right way?

**Technically, yes — genuinely.** 43 migrations in and each one still carries its
reasoning. Multi-tenancy is enforced by composite FKs and RLS rather than by remembering to
add a `where`, and there are tests that prove it. The check scripts caught a stray
untranslated string today without anyone looking. That's better guard-railing than most
funded teams have, let alone a solo evening project.

Today's `facility_hours` is also the first thing built here that isn't module-1-only. "Is
the pool open then" is the same question maintenance windows will ask in phase 4. That's
forward, not sideways.

**But.** Phase 1's stated exit is *"an operator running real classes on Poolse instead of a
spreadsheet."* Three slices are still unticked:

- **1.10 Excel import** — the roadmap literally says *"a customer who cannot get their
  spreadsheet in never becomes a customer"*
- **1.11 Excel export**
- **1.12 role restrictions across module 1**

Today's five commits touched none of them. This was the fourth round of refinement on a
module nobody can be onboarded onto yet. Every individual item was worth doing — the back
button was a real bug, the density really was inconsistent — but four rounds of polish
before the import path exists is a pattern, not a coincidence.

Two other things quietly accumulating: **file storage** is still deferred and now blocks
four features (logo, pool photo, student photo, and now the analysis-report import) — one
decision unblocks all four, and it's been "one decision" for a while. And there are still
**zero real users**, which means the riskiest assumption in the project is no longer a
technical one. The schema is more rigorous than the product is validated.

The roadmap's own "honest risk" section predicted this exact failure mode: *module 1 gets
to good enough, the novelty runs out, and the rest stays perpetually next.* Right now the
symptom isn't losing momentum — it's spending momentum on the comfortable part.

**Next session should be 1.10, not round 5.**
